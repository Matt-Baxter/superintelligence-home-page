# Daily paper watch (for any agent)

What the Claude scheduled task did each morning until 2026-11-07, written so Codex (or another agent) can run it. Once a day at most (free-tier rule). The GitHub Actions workflow `.github/workflows/paper-watch.yml` runs steps 1–2 by itself once it is merged to the default branch; the agent adds paper-to-code, checks and dossiers.

## Steps

0. Clone or update the repo, check out `fix/sync-with-main` (or `main` once it's merged), run `npm ci`, and read `CLAUDE.md` / `AGENTS.md`. Follow the hard rules exactly.
1. **Find papers** from about the last 2 days on arXiv matching the queries in `modules/review/watch.json` (sparse autoencoders, mechanistic interpretability, recursive self-improvement, automated AI research, superintelligence, scalable oversight, reward hacking).
   - With direct network access: `SITE_PROFILE=extended DATA_DIR=out/watch/db node scripts/watch.js` asks arXiv itself (once, 3 seconds between requests).
   - Without it: search the web, read each paper's `arxiv.org/abs/<id>` page, and write `out/watch/inputs/YYYY-MM-DD.json` as `[{"title","url","summary","authors":[...],"note":"summary paraphrased by an agent from the arXiv abstract page"}]`. Check every id exists and matches its title. Skip papers already a `source` in `modules/lab/examples.json`. No Twitter/X.
2. **Run** `SITE_PROFILE=extended DATA_DIR=out/watch/db node scripts/watch.js --from out/watch/inputs/YYYY-MM-DD.json` and read `out/watch/YYYY-MM-DD.md`.
3. **Paper-to-code**, at most one paper: the top one queued (none: skip to 6). Following `modules/lab/papers.js`, build one CPU toy of its core mechanism: deterministic, under 2 seconds, registered in `modules/lab/runners.js`; a Lab example in `modules/lab/examples.json` with `source {title, url, via: "daily paper watcher, <date>"}`, the idea in plain words, a reproduction, and a hypothesis of ours with a predicted metric (keep it even if refuted); checks in `test/papers-unit.js`; one metric in the `papers` suite of `scripts/bench.js`. Never reproduce or attribute the paper's own numbers. Then `npm run lab:results`. Keep `examples.json`'s one-space JSON formatting.
4. **Check**: `node test/papers-unit.js`, `npm run bench`, `SITE_PROFILE=extended npm run build`, `npm run preflight`, and the browser test (`PORT=3200 node test/serve-fixtures.js` in the background, then `npm test`). Record each exact pass/fail line. Don't commit the screenshots the browser test rewrites (`git checkout -- shots`).
5. **Only if everything passes**: branch `feature/paper-watch-YYYY-MM-DD` (add `-b`, `-c` if it exists), run `npm run bench -- --update` only if the new metric is the only change (put back any `info` timing it rewrites), commit without trailers, push that branch. Never push to `main`; never open or merge a pull request. If anything fails, push nothing.
6. **Dossiers**: for each top-level topic today's papers are about, `SITE_PROFILE=extended DATA_DIR=out/watch/db node scripts/dossier.js <topic>`; read `out/dossier/<topic>/post.md` and `social.md`. Don't commit `out/`. Nothing is posted anywhere.
7. **Judge misses**: if the Review desk clearly misjudges a paper, don't change scoring rules unattended. Add a synthetic case that reproduces the pattern to `bench/judge-edge-cases.json` (status `gap`) or `bench/review-set.json`, labelled test data, never the real paper.
8. **Move the backlog along**: run `node test/judge-edge-cases.js`. If a gap now passes, set its status to `ok`. Then do at most one open `[agent]` task from `specs/003-judge-fidelity/tasks.md` (or another spec's `tasks.md`) on its own `feature/` branch, tick it, and say which in the report.
9. **Report**: papers and verdicts, the toy and its verdict at toy scale, the branches pushed, the dossier rating lines and short drafts, the edge-case line, and the exact check results.
