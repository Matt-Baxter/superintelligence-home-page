# Superintelligence Homepage: notes for AI agents

SEIS 606 Project 2 (John Affolter and Matthew Baxter). A multi-source homepage for AI-progress news: stories grouped across sources, tagged against an ontology, judged with an explainable significance score, with accounts, votes, notes, reading lists, a weekly brief and an agent log. Built as a modular monolith: a small core plus plug-in modules (`modules/`: capabilities, admin, project, generative UI, decision judges, json-render blocks, codebase map) loaded by `kernel/` through extension points.

## Hard rules

- **Never push to `main`** and never merge. Work on a `feature/`, `fix/` or `bakeoff/` branch; the human opens the pull request and merges it themselves once preflight is green (no review required).
- **Never deploy** or change Vercel, Neon or GitHub settings. Humans do that ([docs/DEPLOY.md](docs/DEPLOY.md)).
- **Never write agent log entries.** The Agent log page holds entries the humans write in their own words about what the agent got wrong. Don't draft, suggest wording for, or fill in an entry, even if asked to "help with the log". You may remind the human to write one.
- **No secrets** in code, commits or messages. Configuration comes from environment variables (`.env.example` lists them).
- **No Twitter/X** as a source, suggestion or submitted link. It's refused on purpose (Paul's feedback).
- **Spec first.** The shared spec (`specs/001-superintelligence-homepage/spec.md`) and the constitution (`.specify/memory/constitution.md`) decide what gets built. Name the REQ IDs a change serves (commits, PRs, `docs/SPEC_TRACE.md`); work that serves no REQ goes into the spec first, with both partners' approval.
- **Shared documents need both humans.** Changing the spec, the constitution, [CONTRACT.md](CONTRACT.md) or [WORKING_AGREEMENT.md](WORKING_AGREEMENT.md): stop and say so; it needs both partners. This build's own tables, routes and shapes are logged in `docs/INTERFACES.md`.
- **Stay on the free tiers** (Vercel Hobby, Neon Free): no polling, no cron more often than daily, prune what grows, no paid API calls by default.
- **Real people only as watchlist entries.** Never write claims, quotes or results attributed to them.
- **Test data is synthetic** and labelled "Sample" / "test data". Don't invent real-looking papers, people or quotes.

A guard hook (`agent-kit/hooks/guard.js`) blocks pushes to main, merges, deploys and Twitter/X sources, in this repo and wherever the kit is installed as a plugin.

## Where knowledge lives

Load only what the task needs:
1. **This file**: rules and the index below (always loaded).
2. **A skill's `SKILL.md`**: the steps for one kind of job (load when the task matches).
3. **A skill's `references/`**: details, tables and known pitfalls (load only when the skill says to).

New to the code? Start with the codebase-map skill, and ask the map (`npm run codemap -- <question>` or the `codemap_query` MCP tool) before grepping. Before handing work back, use run-tests (or the verifier subagent).

## Checking your work

```bash
npm run preflight     # ~4 s: syntax, build, secrets, no-Twitter, analysis rules, agent kit, contract reminder, API smoke test
npm test              # full two-user browser test against `npm run dev:sample`; must stay at 0 failed
```
Report the exact pass/fail line. Never claim something works that you didn't run.
