## What "live" means here

Self-improvement runs, but unattended edits never reach production rules: a ratchet proposes, the held-out gate (now paradox-aware) decides whether the edit is even offered, and a person applies it (`--apply`) on a branch that passes preflight. Unattended runs may add *synthetic* items that reproduce a misjudgement (`bench/review-proposed.json`); those are reported, never gating, until a person adopts them. This is the point of the rule, not a gap: a loop that grades itself and applies its own edits is exactly where the accuracy paradox does the most damage.

## Next, in order of value

1. Grow the labelled sets until each classifier's 95% interval is narrower than 0.1 (about 40+ items per class at current accuracy), so a regression of a few points is visible. Synthetic items only, labelled "Sample (test data)".
2. Add a held-out split to the review set, as the verification set has, and gate review-rule changes on it.
3. Shrinking for the property generators (report the smallest failing set, not only the trial number).
4. Carry enum value sets into Arrow (a `pa.dictionary` with a checked value list, or a validation step on load).
